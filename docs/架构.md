# 架构

## 运行时

```
酒馆 / TauriTavern ──(发消息)──▶ 面板 src/panel ──┬─▶ 直连：酒馆自己的 Claude 源 / OpenRouter
   （浏览器 / App）                 （改请求参数、     │
                                    检查、灵动岛）    └─▶ 代理 src/proxy（本机 :8901，OpenAI 兼容）
                                                            │  会话续接、缓存排布、防丢回复、额度 / 用量
                                                            ▼
                                                   官方 Claude Code / Agent SDK（后端见 backend-config.js）
                                                            ▼
                                  Anthropic（订阅 / API 密钥）· Bedrock · Vertex · OpenRouter / 兼容网关

手机 TauriTavern ──(同一 Wi-Fi，访问密码)──▶ Mac 上的代理
Mac 启动脚本 launcher/ ──(adb)──▶ 手机：同步、手机模式通知、保活模块（tt-root-module）
```

## 目录

| 路径 | 是什么 | 在哪运行 |
| --- | --- | --- |
| `manifest.json` | 酒馆扩展清单（酒馆要求放根目录），指向 `src/panel/` | — |
| `package.json` | 版本号唯一来源；`main` 指向 `src/proxy/plugin.js`（酒馆服务器插件入口）| — |
| `server.js` | 独立运行代理的入口（`npm start`、启动脚本）。只有一行，转到 `src/proxy/server.js`，留在根目录让老的启动方式不失效 | Node |
| `src/panel/` | 面板：`index.js`、`style.css` | 浏览器 / App WebView |
| `src/proxy/` | 代理：监听、请求改写、会话、缓存诊断、额度、遥控；`paths.js` 统一给出仓库根目录和 `data/` | Node |
| `src/shared/` | 面板和代理 / 开发脚本共用的纯函数：体检、角色卡检查、世界书常驻、预设推荐、灵动岛、云端酒馆检测 | 两边 |
| `bin/claude-cli.js` | 调用随附的 Claude Code（登录、查登录状态：`npm run login`）| Node |
| `launcher/` | 一键脚本：`menu.mjs` 是三个系统共用的菜单，`core.mjs` 是共用的状态和动作（都无 npm 依赖，见下面「启动器」）；`mac/`（`酒馆工具.command` 启动壳、`actions/*.zsh` 各项动作、`lib.zsh`、`menu-status.zsh`）、`windows/`（`酒馆工具.bat` + `claude-max.ps1`）、`termux/`；`phone_sync.py` 同步；`使用说明.txt` | 用户电脑 |
| `test/` | 单元测试：`*.test.js`（`npm test`）；`test/launcher/`（Python，`npm run test:py`）| 开发 / CI |
| `scripts/` | 开发脚本：门控 `gate.sh`、版本 `version.mjs`、灵动岛示意图 | 开发 |
| `docs/` | 设计文档（定位、架构、版本规范）和 `assets/` | — |
| `data/` | 运行时数据：用量、缓存记忆、调试记录。本机专用，不进仓库 | — |

## 启动器

- `launcher/core.mjs`（Node，三个系统同一份）：读 `config.local` / `config.local.ps1`、问代理（`/status`、`/v1/control/status`）、版本对比、登录、装了什么（酒馆、TT、ComfyUI、保活模块）、端口探测、上次同步时间；动作「检查状态」，以及 Windows / Linux 上的启动、关闭、重启。
- 关程序只按 PID：端口上监听的进程，再确认是我们的（工作目录在程序目录里、`data/logs/*.pid` 记下的、或代理 `/status` 报的 `pid`），从不按名字。重启前问代理 `busy`，在写回复就拒绝。
- 留在各系统脚本里的：Mac 的手机（adb）、合盖、守护、Mac App 在不在跑（`mac/menu-status.zsh`，只剩这些）；Mac 的启动 / 关闭 / 重启（要连带手机模式守护和合盖）；手机同步、保活模块、登录、生图。Windows 的 `claude-max.ps1` 只剩登录、修复依赖、开机启动、日志；Termux 的代理在 Debian 子系统里，启停仍由 `termux/claude-max.sh` 做。别的系统上没有的状态显示「只支持 Mac」。

## 两种安装方式都要能用

- **扩展安装**：酒馆「安装扩展」填仓库地址 → 整个仓库克隆到 third-party，酒馆按 `manifest.json` 加载 `src/panel/`。
- **服务器插件**：`plugins/` 下克隆 → 酒馆加载 `package.json` 的 `main`；插件启动时把面板用到的文件（`UI_EXTENSION_FILES`）复制到 third-party，已经用扩展安装过就跳过。
- 挪动面板文件时，两处都要跟着改：`manifest.json` 和 `src/proxy/plugin.js` 的 `UI_EXTENSION_FILES`。

## 约定

- 路径一律从 `src/proxy/paths.js` 取，不在各文件里数 `..`。
- 面板不静态导入酒馆模块（只用 `SillyTavern.getContext()`），所以装在哪个位置都能用；`src/shared/` 用动态 `import()` 加载，缺了只影响对应功能。
- 本机文件（`launcher/*.local`、`data/`）不进提交，门控会拦。
