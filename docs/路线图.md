# 路线图

> 2026-09-26 · 基于 3.1.x。计划会随反馈调整，版本号是目标不是承诺。

## 目标

**酒馆里用 Claude 的懒人层：不管 Claude 从哪来，装上就是最好的状态。**

订阅、官方 API 密钥、OpenRouter、AWS Bedrock、Google Vertex、各种 OpenAI 兼容中转，今天在酒馆里各有各的坑：缓存要自己调、新模型要手动加、预设和模型对不上、手机切后台回复就丢、电脑和手机两头不一致。CCST 要做的是：选好来源、点一次连接，剩下的自动处理。

## 现在（3.1）

| | 订阅（本机代理） | 官方 API / OpenRouter（直连） | 其他来源 |
| --- | --- | --- | --- |
| 面板：模型切换、预设推荐、发送前检查、体检 | ✓ | ✓ | 部分（按 OpenAI 兼容处理） |
| 缓存排布（世界书挪位、会话续接） | ✓ | 用酒馆自带设置 | – |
| 防丢回复、额度 / 用量、手机遥控 | ✓ | – | – |
| Mac ↔ 手机同步（含 API 设置和密钥） | ✓ | ✓ | ✓ |

## 3.2 · 所有来源一个面板（已完成）

酒馆本身没有 Bedrock 来源，「Vertex AI」来源只接 Gemini，所以这两家只能经中转接入；酒馆的缓存设置在服务器 `config.yaml` 里，面板只能给出改法，不能代改；直连时酒馆不把用量传给网页，上一轮命中看不到。


- 面板识别全部来源：Claude 官方源、OpenRouter、Bedrock、Vertex、自定义 OpenAI 兼容地址，状态栏写明「现在走哪、按什么计费」。
- 每种来源给出缓存建议并一键套用酒馆原生设置（`cachingAtDepth`、1 小时缓存），面板显示上一轮是否命中。
- OpenRouter / Bedrock / Vertex 的模型切换和「按模型自动切换思维链」（现在只支持官方源和本代理）。
- 新模型不用等更新：从来源的模型列表自动补全。

## 3.3 · 代理多后端

- 代理后端可选：订阅（Agent SDK）、Anthropic API 密钥、Bedrock、Vertex、OpenRouter。缓存排布、防丢回复、用量统计对所有后端生效。
- 面板里切后端，不用改环境变量；每个密钥只发给它自己的服务。
- 用量按后端分开统计，API 类后端显示实际花费。

## 3.4 · 一键部署

- 扩展：酒馆「安装扩展」填仓库地址即可，首次打开有引导（选来源 → 连接 → 完成）。
- 代理：Mac 已正式；Windows、Linux、Termux 真机实测后转正。
- 云酒馆：服务器上一条命令装代理，自动生成访问密码；提供 Docker 镜像。

## 3.5 · 手机与多客户端

- 安卓多客户端：TauriTavern、SillyDroid、Termux 版酒馆都能装面板、连代理（兼容测试由 [tt-root-module](https://github.com/kcgoofee-jpg/tt-root-module) 协助）。
- 不需要 root 的同步方案（局域网直传，面板里操作）；有 root 时继续用现在的全自动同步，整份备份由 root 模块负责。

## 之后

- 长聊天管理：分卷、摘要和缓存配合，不让总结插件把缓存打碎。
- 预设体检：静态检查预设和当前模型是否匹配（思维链条目、段落计划、正则）。
- 生图联动：生图请求的状态进灵动岛，失败原因直接显示。

## 不做

- 订阅共享、拼车、多账号轮换、对外服务。
- 规避安全机制：拒绝后自动换模型重试、改写内容绕过审核。
- 涉及未成年人的内容：不导入、不调优，角色卡检查会提示。
